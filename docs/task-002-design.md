# Task 002 — Victoria Memorial

The Task 002 brief authorises autonomous modelling, import, integration and QA. Studio owns the existing world. No automatic sync or Git repository currently exists. Preserve Para01, its kits, lights and spawn.

## Asset design

Create an original stylised interpretation informed by the Memorial's official architecture page and exterior photographs. Preserve the broad marble massing, high terrace, ribbed central dome and lantern, bronze Angel of Victory, four subsidiary chhatris, four corner towers with Mughal dome profiles, monumental portals, paired columns, long facade rhythm and curved side colonnades. Simplify relief and sculpture into readable original forms. No reference image becomes a game texture.

Approximate building footprint: 260 × 180 studs, height about 140 studs. Ground floor at 6 studs. This compresses the real campus while retaining a large hero silhouette relative to the existing 12–14 stud storeys. Formal grounds span roughly 500 × 540 studs. Confirm final placement against the live scene before baking.

Blender owns editable mesh sources and exports; Studio owns the integrated assembly and grounds. Use repeated mesh templates with plain Roblox-compatible colours, native box collision and floor pieces, a hollow rotunda, connected gallery shells, front/rear entries and side service access. No runtime generator, robbery code, remotes or external model dependency.

## Execution and checks

1. Inspect live scene and references; preserve a recovery snapshot before edits.
2. Build Blender source and modular export, recording geometry counts and instances. Inspect exterior angles before import.
3. Import modules into Studio, retain shared mesh identities for repeated components, assemble using an explicit manifest and add simple structural collision.
4. Build formal lawns, paths, shallow ornamental pools, original vegetation, boundary/gates, vehicle apron and perimeter road connected to Para01's east road.
5. Inspect actual Studio views, normals, materials, scale, interior and approaches. Walk entrances, galleries, exits and paths in a local client. Check collisions, scripts, anchoring, IDs and output. Record rendering counts where available. Do not turn viewport emulation into a mobile performance claim.
6. Save source, exports, integrated recovery package and a concise factual verification report. Do not publish the experience.
